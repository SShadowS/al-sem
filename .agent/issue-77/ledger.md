## Design

Revision 2.

**Goal.** `digest --diff` resolves a diff made at the enclosing git repository's root to the same roots as the workspace-relative diff; `--diff-root <dir>` states the base folder for workspaces outside git and diffs made elsewhere; a path that could name two different workspace files is refused, never picked silently.

**Non-goals.** No change to `diff_parser.rs`. No `git` subprocess. No auto-detected prefix for plain `diff -ru` from a parent folder. No change to `--file`/`--changed-files` (discovery D1). No use of a rename's `old_path`. No change to human output (discovery D2).

**Choice: auto by default, plus `--diff-root`.** Auto, because `git diff` always writes root-relative paths (P0b), so CentralGauge works with no flag. `--diff-root`, because auto cannot help outside git (P3) or for `diff -ru` from a parent folder (P8). The top level is the nearest folder at or above the canonical workspace that holds `.git` (folder, or file for a worktree/submodule), probed with `plan_exists`, no depth cap — chosen over `git rev-parse` (runtime git dependency, a process spawn, `safe.directory` failures).

**How a diff path is read.** Every reading is checked against the workspace's FILE set (`al_files`), not routine spans (S1).
- `Workspace` (no repository, the workspace is the top level, or no diff): the path as written.
- `GitTop(prefix)`: two readings, in order: as written, then with the prefix removed.
- `Explicit(prefix)` (`--diff-root`): only the prefix-removed reading; a path not below the workspace is unmatched (strict).
- The prefix keeps its case and is compared folder by folder, **exactly, on every platform** (S2, revision 2.1): platform is not filesystem identity (case-sensitive APFS/NTFS folders exist), and an exact comparison can only leave a path unmatched, never attribute it to a case-distinct sibling. The prefix is derived from the workspace's real on-disk spelling, which normally matches git's tracked spelling — but not always: on Windows a case-only folder rename on disk leaves git's index, and so `git diff`, on the old case (base was unmatched there too, so this is not a regression; Opus N8). Below the workspace the existing lowercased key stays. A diff whose prefix spelling differs only by case from the workspace's on-disk folder is `diff-file-unmatched`; the general remedy is a workspace-relative diff (`git diff --relative`). Re-spelling the workspace argument does NOT help in auto mode, because auto derives its prefix from the canonical (on-disk) workspace path; it helps only with `--diff-root <repo top>`, whose lexical branch compares the paths as typed, so the workspace path spelled below the root the way the diff spells it gives that prefix (sol/Opus r4).
- Workspace files include every `al_files` entry, nested apps' files too (inputs.rs:64-65, 380-387): a nested app's file can make a path ambiguous — intended, since it only causes a refusal, never a wrong root (Opus N3).
- Zero readings, or one reading whose file holds no routine → `diff-file-unmatched` (base behaviour). One reading → that file. Two readings → `diff-file-ambiguous {file, candidates}` and no roots from that record. Candidate order is a contract: the as-written reading's units first, then the git-top reading's, each list sorted, all units of a reading included (S7). Exit 2 only if nothing else resolved.

**Ambiguity and the #72 veto (S3/O5).** For a file with a broken hunk header, every reading of its path is blocked: an ambiguous broken record blocks BOTH candidates, in any record of either, whether or not the parser emitted a record for it. Blocking rather than requiring disambiguation: #72's rule is "no diff-derived roots from a file whose changes are unknown"; with two possible files both are unknown; blocking stays local to those two keys and uses the lookup's key set, whereas requiring `--diff-root` would also discard roots from unrelated files.

**Decision pinning (S4/O3, O1, S6).** `decide_diff_root(d)` runs once per run: standalone in `plan_digest`; in batch, the parent runs it per job after the `PLAN_TOUCHED` clear (so the `.git` probes join that job's reads) and carries the result, failure included, as `WorkerJob.diff_root: Option<Result<DiffRoot, String>>`, like `changed_is_file`; the worker calls `pin_diff_root(job.diff_root)` and never re-decides. Auto mode never fails: a workspace that cannot be canonicalized gives `Workspace` (O1). `--diff-root` errors: the root must first exist and be a directory (checked before either containment test, so a lexical success cannot bypass it; sol r2 new finding), else exit 3; then the workspace's path below it as spelled (`std::path::absolute`, rejected if the remainder holds `..`), then the canonical path; neither → exit 3 (`workspace '…' is not inside --diff-root '…'`, or a canonicalize error). A lone `--diff-root` without a diff is exit 3 before the no-input check (S6).

**Schema contract (S5/O2) — bump to 1.7.0 (operator decision).** Digest `schemaVersion` 1.6.0 → **1.7.0**, following #69 (a minor bump for a new default-on diagnostic); this kind is default-on and adds a `candidates` key.
