# B3 Phase A: alsem's detectors read the program engine's call resolution

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Behind a switch, replace the L3 call resolver's output with the program engine's resolved edges — detector code unchanged — prove every resulting difference in findings is a fix, then make it the default.

**Architecture:** An adapter turns the program report's call-site edges into L3's existing `ResolvedCalls` shape, joined to L3 call sites by exact source span (both engines use byte columns). A seam on `L3Resolved` lets every place that resolves calls use the precomputed result. A difference harness runs every detector both ways and produces a triage table. Event links, operation sites and L2 body facts are untouched.

**Tech Stack:** Rust 2024; `ProgramContext`/`ProgramReport`/`ClassifiedEdge` (program engine); `L3Resolved`/`ResolvedCalls`/`CallEdge`/`UpgradedBinding` (L3); `run_detectors`.

**Spec:** `docs/superpowers/specs/2026-10-04-compact-graph-core-design.md` §7. **Code map (file:line evidence for everything below):** `docs/2026-10-04-b3-code-map.md` — read its headline findings, A2 (field table), A3 (join keys), A4 (dependency callees), B7 (conversion table), C9-C10 (goldens, harness).
