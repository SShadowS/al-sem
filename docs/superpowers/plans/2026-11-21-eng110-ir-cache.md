# ENG-110 Persistent Dependency IR Cache Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Engine processes of one binary stop re-parsing CDO's ~10,900 dependency files: the first
process writes each package's lowered IR to a private on-disk cache, later processes read, hash and
decode it.

**Architecture:** A new `src/program/ir_cache/` module keys entries by the blake3 of the running
image (`/proc/self/exe`, Linux only) and names them by ENG-113's verified text digest. The two
dependency-parse seams in `src/program/dep_summary.rs` call one per-package function that either
decodes an entry (whole-envelope blake3, exact index) or parses an owned copy of the ENG-113 entry,
round-trips each file's encoding, and publishes under ENG-113's `CacheDir` rules. Only the
`alsem`, `aldump` and `al-call-hierarchy` `main`s install the cache; tests and in-process binaries
never see it.

**Tech Stack:** Rust 2024, serde + postcard (already in the lock), blake3, libc `flock`/`openat`,
bash and Python gate scripts.

**Spec:** `docs/superpowers/specs/2026-11-18-eng110-ir-cache-design.md` (rev. 7, amended
2026-11-21). Read it first; this plan argues from it and does not repeat its reasons.

## Global Constraints

- Linux only in v1; on any other target `IrCache` is never built and reports say `unsupported`.
- `IR_KEY` = blake3 of the bytes of `/proc/self/exe` plus `IR_FORMAT: u32 = 1`; no sidecar; hashed
  once per process at the first seam use; no key when the image lacks the marker.
- Layout `<root>/ir/<IR_KEY 64 hex>/<text digest 64 hex>.bin`; `<root>` = `snapshot::cache::cache_dir()`;
  `ALSEM_IR_CACHE_DIR` replaces only the `ir/` tree.
- Envelope magic `ALSEMIR\0`; per-entry cap 1 GiB (read and write); per-file encoded cap 64 MiB.
- Soft total target 4 GiB under `ir/`; prune throttle 1 hour; `last-used` refreshed when older than
  1 day; key folders pruned after 7 days; temp files after 1 day.
- Env: `ALSEM_IR_CACHE` (`on`/`off`, default on in an installed `main`), `ALSEM_IR_CACHE_DIR`,
  `ALSEM_IR_CACHE_VERIFY=1`, `ALSEM_IR_CACHE_REPORT=<file>`.
- Batch (`claim::dir().is_some()`): no read, write, prune or report line.
- Round trip at publish: `decode(encode(ir)) == ir` AND `encode(decode(encode(ir))) == encode(ir)`.
- Acceptance bars: warm ≤ 0.70, cold ≤ 1.05, off ≤ 1.01 of master's instructions (median of 6
  per-round ratios; 6 more rounds when within 0.01 of a limit). Any `roundtrip_failed > 0` on CDO
  fails.
- Repo rules (CLAUDE.md): edit with Edit/Write only; `rustfmt <file>` per file, never `cargo fmt`;
  the package is `al-sem` (`cargo test -p al-sem --lib …`); every correctness guard gets one
  discrimination proof made and reverted with Edit, both outcomes recorded in the commit message;
  builds and tests only as `scripts/cdo-slot status && <cmd>`; never pipe a gate through `tail`.

## Review Focus

1. **The disk fills up mid-publish** (ENOSPC while writing the temp file): the process keeps its
   parsed IR, nothing appears under the entry name, the temp file is removed. Test in Task 4.
2. **The cache root is read-only or not private** (another user's group-writable `~/.cache`): the
   analysis still runs with identical output and `skipped_off` counts every seam file. Test in
   Task 7.
3. **Two engines publish the same package at once** (two lanes' `alsem mcp` starting together): one
   entry, the second counts `publish_skipped_busy`, both models equal cache-off. Test in Task 7.
4. **A writer is killed mid-fill** (`kill -9` during a cold analyze): the next run is unaffected and
   the leftover temp file is pruned after a day. Test in Task 8.
5. **A symbol-only dependency or a package below the small threshold**: no entry, no crash,
   `skipped_small` counts it, and `eligible_files` excludes it. Test in Task 7.

The per-package algorithm (`seam.rs`), in order:
1. count `seam_files += n`; no cache, no `text_digest`, or no key → parse all, `skipped_off += n`;
2. below the small threshold → parse all, `skipped_small += n`;
3. `eligible_files += n`; open `ir/<key>` (no handle kept between packages); `read_owned` the entry
   (cap `MAX_ENTRY`) → `open_envelope`; on success decode each stored slice inside the `par_iter`
   (`disk_hits`, and under VERIFY also parse and compare: mismatch → panic naming package, file,
   key; else `verified_hits`), parse not-stored ones (`skipped_unstored`); a decode error → parse,
   `refused`, and mark the package for refill;
4. otherwise (missing or refused) a fill: `read_owned` the ENG-113 entry
   (`snapshot::cache::text_entry_name`) and `check_entry`; if its digest ≠ the carried digest →
   parse from `unit`'s mapped files, `fill_text_changed += 1`, publish nothing; else parse each file
   from the owned texts (giving `ParsedFile.text` the unit's mapped `SourceText`), encode,
   `round_trip_ok` (fail → `NotStored`, `roundtrip_failed`, warn once), over `MAX_FILE` →
   `NotStored`; `parsed_miss += n`;
5. publish: `subdir(ir, true)` → `subdir(<key>, true)`; take `folder.lock` `SharedNow` (busy → skip),
   then the entry's lock `ExclusiveNow` (busy → `publish_skipped_busy`, skip); re-read the entry and
   publish only if missing or refused; for a refill whose new bytes equal the stored bytes, publish
   nothing; refresh `last-used` (Task 8); `published_packages += 1`.
