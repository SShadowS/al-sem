## What the LSP reads

Production LSP code reads `edge.from`, `edge.kind`, `edge.site.span` (start/end) and
`route.target` (`Routine` for `incoming`/outgoing items, `AbiSymbol` for outgoing items;
`Builtin`/`Unresolved` give no item). It never reads `witness`, `evidence`, `conditions`,
`shape`, `completeness`, `receiver_tier` or `site.caller`; `obligation_id` only in tests and
the debug check. The edge COUNT is read: the CLI index report and session telemetry count
call sites.

## Design

- **`LspEdge`** (`src/lsp/snapshot.rs`), the LSP's stored form: `from`, `kind`, `span`
  (`LspSpan`: the file as a `SharedStr` made once per file, plus start/end), `callee_fp`, and
  `targets: Box<[LspTarget]>` with `LspTarget::{Routine(RoutineNodeId), Abi(Box<AbiRoutineKey>)}`.
  Every call site is kept (counts unchanged), with only its LSP-visible targets.
- **Projection** (`LspEdge::project`) right after resolution, per file and per event link; the
  resolver and the program report are unchanged (classification still runs on the complete
  edge; `FULL` keeps everything). `obligation_id()` recomputes the identity (a call site's
  caller, span and callee fingerprint; a publisher); a debug assertion checks it equals the
  resolver's.
- Readers (`edge`, `incoming`, handlers, the rung-1 patch, `DepEventLinks`) move to
  `LspEdge`. Tests that asserted resolver facts (evidence) through the LSP snapshot assert them
  on the program report or the resolver instead; tests comparing the snapshot with the report
  project the report's edges.

## T1 record (`551f526d`)

Task gate green; both CDO stats JSON files byte-identical to the S10.1b binary's (`cmp`); no
golden moved. The fixture has no ABI route, so the planned "every LSP edge equals the
projection" test could not carry the `AbiSymbol` discrimination; it was split in two:
`project_keeps_the_routine_and_abi_targets_and_counts_every_route` (a hand-built edge with a
routine, an ABI, a builtin and an unresolved route) fails when the `Abi` target is dropped, and
`a_call_site_without_an_lsp_target_is_kept` (`Message('x')` plus a local call) fails when
target-less sites are dropped; the existing tests passed that second break. Both reverted and
green. `build_full_edges_match_resolve_full_program` now compares with the report's edges
projected. The arity test's `Evidence::Unknown(ArityMismatch)` check now runs on a fresh full
resolve of the edited files (`resolve_full_program`), not on the rung's own output.

**What the rung tests no longer check.** The LSP drops shape, completeness, conditions and
evidence right after resolving, so a rung-1/rung-2 drift in those alone is invisible to every
LSP consumer, and no test checks it any more. The goldens cover the full-build resolver, not the
rung path (both call the same resolver functions). Narrowed in the same commit:
- `tests/lsp/lsp_incremental_parity.rs` compares (obligation, kind, targets, route count); its
  `canon_edge` meta-test lost the shape, completeness and condition cases (a route-count case
  was added).
- The rung-1 Calc test checked `Evidence::Source`; it now checks one route whose one target is
  a routine (tightened to name `LspTarget::Routine` in T2, after the audit; expecting `Abi`
  instead fails it, reverted and green).
- `debug_assert_same_dep_links` (S10.4) now compares `LspEdge`s.
