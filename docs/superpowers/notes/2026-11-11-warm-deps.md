# TLS-08: seeding a new worktree's build folder (2026-11-11)

**Question.** A new git worktree has an empty `target/`, so its first build compiles every
dependency again. Does copying the main checkout's `target/` into it first save time?

**What `scripts/seed-target <worktree> [--from <dir>]` does.** It copies
`$(dirname git-common-dir)/target` (the main checkout's build folder, 26 GB here) into
the worktree with `cp -a --reflink=always`. A reflink copy shares the disk blocks until one
side writes, so it takes seconds and no extra space. It skips `flycheck0/` and `tmp/`, and
refuses a worktree that already has a `target/`. If the copy fails (another filesystem, no
reflink support) it deletes the partial copy and exits 1, and the build runs cold as before.
agentflow already seeds its issue worktrees the same way (`scripts/agentflow/worktrees.py`).

## Measurement

- Host: server1 kraken container, 22 cores, btrfs, no other build or gate running
  (checked before the start; MemAvailable 36.3 GB). 21:33-21:45 UTC.
- Revision: master `c498fd98` (3.0.0, grammar 5.2.0 `f8c6d8b6`).
- Command: `cargo nextest run --workspace --no-run`, the build half of the task gate's
  test step, in a fresh worktree each time. 3 rounds, cold and seeded alternating, each
  worktree removed after its run.
- Seed source: `/work/alsem/target`, last built 2026-11-10 at an OLDER revision. So the
  workspace crates rebuild anyway; what the seed saves is the dependencies.
- Script and raw rows: `warm-deps/tls08-measure.sh`, `warm-deps/tls08.jsonl`.

| Run | Seed (s) | Build (s) | Units compiled |
|-----|---------:|----------:|---------------:|
| cold 1 | - | 146.3 | 257 |
| cold 2 | - | 145.8 | 257 |
| cold 3 | - | 147.6 | 257 |
| seeded 1 | 1.8 | 94.5 | 3 |
| seeded 2 | 1.6 | 94.3 | 3 |
| seeded 3 | 1.5 | 93.7 | 3 |

**Result.** Median cold 146.3 s, median seeded 94.3 s plus 1.6 s for the copy: **~50 s
(34%) saved** on the first build of every new worktree. A seeded build compiles only the
three workspace crates (`al-sem`, `al-syntax`, `xtask`); the 254 dependency units are reused.
The spread is under 2 s on both sides, far below the difference.

**A fixed build path per lane: not done.** The only units a seeded build still compiles
are the workspace crates, and those changed between the seed's revision and this one, so a
fixed path could not have saved them. Nothing is left for it to win here.

**Limits.** One host, one revision pair, a quiet machine. The saving shrinks as the seed
folder ages only if dependencies change (Cargo.lock); the workspace crates always rebuild.
