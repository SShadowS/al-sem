# #160 step 11b (routine identity corrections, `RoutineIx` re-keying, the one rule): numbers

Spec: `docs/superpowers/specs/2026-10-22-issue-160-step11b-routine-rekeying-design.md` §8.
Plan: `docs/superpowers/plans/2026-10-22-issue-160-step11b-routine-rekeying.md`.

11b is non-speed (Decision 58): **no bench**, no wall or peak bound. Each stage is closed by a
fail-closed identity run instead: `identity-run.sh` + `idcheck.py` (bench folder
`/work/bench/160-11b/`), left = the previous stage's commit, right = this stage's, both built
with the `cdo` profile from clean detached worktrees and run through
`agentflow run --name bench`. One run = the CDO call-graph histogram (byte compare) plus
`alsem analyze` on CDO and on every fixture dir with an `app.json` (246 dirs), each in both
universes (cross-app, `--single-app`), both scopes (`primary`, `all`) and both formats (SARIF,
JSON): 3,952 analyzer runs, 1,976 exhaustive diff reports. `idcheck.py accept` checks every
report against the stage's expectation file.

**C's move (R-MOVES, spec §3.4), the only output change of 11b.** The caller check reads each
row's own node, so the 5 sites of the first `#if` arm of the Base Application's
`GetPurchaseHeaderPageID` (`PageManagement`) resolve to the program's edges instead of
`Unknown(NoProgramSite)`; one of them raises `OnAfterGetPurchaseHeaderPageID`. In each of the
4 cross-app CDO reports (`--scope primary` and `--scope all`, SARIF and JSON) exactly 14
`d9-transaction-span-summary` results move, each message-only, "publishes N event(s)" +1, by
span root: `RunExportEDocReport`, `RunExportEDocCodeunit`, `OpenDOMail`, `PrintDocuments`,
`Run`, `PostAndHandle` (x3), `PrintOrEMailAll`, `SendPeriodStatements`,
`CreateOrSendAutStatements` (x2), `CalcSalesDisc`, `LogUsage`. The other 20 `d9` results per
report do not move. `expect-C-exact.json` pins each moved result by rule, fingerprint and
location. Every other report (single-app CDO, every fixture) is identical.

**A and B** are predicted byte-identical (spec §3.5): B changes rules only for collided ids,
and on CDO those are 4 dependency rows of `PageManagement` whose direct facts and coverage are
equal and whose edges were already unioned.
