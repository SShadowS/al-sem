# B3 Phase A — code map (read-only study)

Repo `U:/Git/al-call-hierarchy`, master @ `bcf799a6`. Spec: `docs/superpowers/specs/2026-10-04-compact-graph-core-design.md` §7.
All paths are repo-relative. "L3 call edge" = `engine::l3::call_resolver::CallEdge`.

## Headline findings (read these first)

1. **`resolve(&mut ws)` does NOT resolve calls.** It runs only record-type resolution and the
   extension-field merge (`src/engine/l3/l3_workspace.rs:1623-1649`). Call resolution is a
   separate, pure function, `resolve_calls(ws, &symbols, deps, fetched) -> ResolvedCalls`
   (`src/engine/l3/call_resolver.rs:805-850`). It writes NOTHING into `L3Routine` or
   `PCallSite`; it returns a value. That value is the whole Phase A seam.
2. **There are two call-resolution sites on the `analyze` path, not one.**
   `build_detector_context` calls it (`src/engine/l5/detector_context.rs:884`). The lazy
   ordering facts used by d47/d49/d51 call it AGAIN, on their own:
   `DetectorContext::get_ordering_facts` (`detector_context.rs:807-822`) →
   `compute_ordering_facts` (`src/engine/l5/ordering_facts.rs:212`) →
   `compute_digest_effects_for_ordering_with` (`src/engine/l5/digest.rs:3454`; renamed in
   task 7b) → `compose_snapshot`
   (`src/engine/l5/snapshot.rs:1014`) → `build_r3a3_source_only_base`
   (`src/engine/l4/capability_cone.rs:3537-3542`, `resolve_calls` at 3542). Spec §7 does not
   mention the second site. If only the first is swapped, d47/d49/d51 silently keep the old
   resolution.
3. **The spec's UTF-16 premise is false. Both sides use byte columns.** `Utf16Cols::col`
   returns the byte column unchanged (`src/engine/l2/node_util.rs:20-38`, "EMPIRICAL FINDING
   (R1a Task 2)… identity pass-through"). L2's anchor builder is `SpineCtx::anchor`
   (`src/engine/l2/ir_walk.rs:262-276`; the spec's 279-294 points at `lit_text`). Program
   sites use `byte_to_pos` (`src/program/resolve/extract.rs:283-292`), also byte columns.
   Both anchor the SAME IR node, the `Call` expression's origin (L2: `ir_walk.rs:946`
   `self.anchor(&e.origin)`; program: `extract.rs:637-641`). So an exact span join needs NO
   column conversion. The docs that say otherwise are stale: `src/program/l3_mint.rs:71-77`,
   `src/program/resolve/differential.rs:297-300`.
4. **The two engines read different workspace file sets and different text.**
   L3: `discover_al_files_app_scoped` stops at any nested `app.json` and skips only
   `node_modules`/`.alpackages` (`src/engine/l2/l2_workspace.rs:128-170`); it strips a UTF-8
   BOM and decodes lossily (`l2_workspace.rs:172-177`).
   Program: `walk_al_source` walks everything, including nested-app folders, and skips
   `.alpackages`/`.snapshots`/`node_modules` (`src/snapshot/provider.rs:32-75`); it does NOT
   strip a BOM and fails the whole snapshot on non-UTF-8 (`provider.rs:48-49`).
   Consequences: (a) the join will have unmatched sites by construction (nested apps,
   `.snapshots`); (b) on a BOM file, line-0 spans are 3 bytes off and the parser sees U+FEFF;
   (c) "one parse" (§7 Phase A, spec line 253) cannot be a drop-in, because it would change
   which files L2 sees. A BOM-less workspace program source is a separate program-engine bug
   worth its own check.
5. **The existing L3-vs-fresh site matcher must not be reused as the adapter.**
   `differential::match_sites` (`differential.rs:290-408`) ignores columns (because of the
   wrong UTF-16 belief) and pairs same-line, same-callee sites by position. With byte columns
   on both sides, an exact `(unit, start, end)` key is available and strictly better. Its
   helpers ARE reusable: `callee_fp` (`src/program/resolve/edge.rs:659-664`, "BOTH the fresh
   and L3 projections must use THIS function"), and the "strip `ws:` from `source_unit_id`
   → program `virtual_path`" rule (`l3_mint.rs:127-131`).

### A3. Identity

- **L3 routine id**: `L3Routine.id` = `{modelInstanceId}/{canonicalKeyHash}` from
  `compute_routine_id` (`src/engine/l2/scope.rs:111-143`): app guid, object type, object
  number, routine kind, name, enclosing member, parameter type+var specs, return type.
  `stable_routine_id` = `{stableObjectId}#{hex}` (`l3_workspace.rs:416-422`), used in
  `rootCauseKey`. `object_id`, `app_guid`, `object_number`, `object_type`
  (`l3_workspace.rs:423-437`). Ids can still collide (preproc `#if` alternatives, XMLport
  nesting; `detector_context.rs:967-1057`).
- **Program routine id**: `RoutineNodeId { object: ObjectNodeId{app: AppRef, kind, key:
  ObjKey}, name_lc, enclosing_member_lc, params_count, sig_fp }` (`src/program/node.rs:117-122,
  174-206`); `NodeId = RoutineNodeId` (`edge.rs:34`). No model-instance id, no return type.
- **L3 call site**: `PCallSite { id, operation_id, callee_text, callee: PCallee,
  argument_bindings, source_anchor: PAnchor, ... }` (`src/engine/l2/features.rs:131-178`),
  built at `ir_walk.rs:907-954` for every `Call` expression that is NOT a record op and NOT
  `Commit`. `source_anchor` = the Call expression origin, `source_unit_id = "ws:<rel posix
  path>"`, 0-based row, byte column.
- **Program call site**: `SiteId { caller: RoutineNodeId, span: CanonicalSpan{unit =
  virtual_path, start, end}, callee_fingerprint }` (`edge.rs:72-92`), built per Call
  expression by `collect_calls_v2` (`extract.rs:625-660`), sorted by start
  (`extract_sites_for_routine`, `extract.rs:952-980`), one `Edge` per site
  (`full.rs:696-754`). Includes record ops and `Commit` (`CalleeShape::RecordOp`/`Commit`,
  `extract.rs:74-77`).
- **What a join needs**:
  - Site: exact key `(unit, start.line, start.col, end.line, end.col)`, with unit =
    `source_unit_id` minus `"ws:"`. Check `callee_fp(PCallSite.callee_text)` equals
    `site.callee_fingerprint` as a sanity check, and count disagreements. Nested calls on
    one line have different spans, so no positional pairing is needed.
  - Caller check and workspace callee → L3 id: both engines keep the routine's IR
    declaration origin. L3: `L3Routine.source_anchor = anchor_from_origin(&ir_routine.origin)`
    (`l3_workspace.rs:1205`). Program: `DeclSurface::get_with_path(id)` →
    `RoutineMeta { origin, virtual_path, params[].by_ref }`
    (`src/program/resolve/decl_surface.rs:44-55, 144-150`). Join on `(virtual_path,
    origin.start)`. No recomputation of hash ids, no model-instance id needed.
  - Implicit-trigger edges: L3 keys them by `L3RecordOperation.id`, with the op's own
    `source_anchor` (`implicit_edges.rs:104-108`, `l3_workspace.rs:1029`). Join program
    `EdgeKind::ImplicitTrigger` edges to record ops by the same exact span.

### A4. Dependency callees

L3 is workspace-only, so a call into a dependency becomes:
- object-typed variable whose object is absent → to-less `Method` edge, `ExternalTarget`
  (or `Opaque` if a declared dep is unfetched; always `ExternalTarget` on analyze because
  deps are passed empty, `detector_context.rs:882-884`) + `external_type_ref`
  (`receiver_type.rs:1085-1107`) → `"external-target"` uncertainty → cappedBy
  `"opaque-callee"`;
- a method on a dependency TABLE record (e.g. a Base App table procedure) →
  `Unknown(RecordTableProcedure)` → `"unresolved-call"`;
- `Codeunit.Run(X)` with X absent → `Opaque` → `"unresolved-call"` (`call_resolver.rs:640-646`,
  `combined_graph.rs:313-318`);
- bare call to a base-object procedure absent from the workspace → `BareUnresolved`;
- record op on a dependency table → no implicit-trigger edge and NO uncertainty
  (`implicit_edges.rs:74-84`).
In every case `to == None` and the bindings stay `"unresolved-callee"`.

**What detectors do with `to == None` + bindings:** roles composition skips the call
(`summary_runner.rs:638-660`: unresolved binding → `continue`; resolved binding with no
edge → `continue` at 660-663); CFG walker treats an edge-less but resolved binding as an
OPAQUE callee and joins `Unknown` (`cfg_walker.rs:1218-1235`), but an unresolved binding
as "no forwarding" (`cfg_walker.rs:1186-1209`); d37 returns `"suppress-unknown"` for an
unresolved binding (`d37.rs:219-221`) but `continue` for a resolved by-value one
(`d37.rs:223-225`); d39/d41 need a callee role or `routine_by_id` hit, so dependency
callees never fire there (`d39.rs:85-96`, `d41.rs:67-74`).

**Recommended Phase A shape for a dependency callee** (keeps every detector unchanged and
does not invent nodes): `CallEdge { to: None, resolution: ExternalTarget, dispatch_kind:
<from the L2 callee shape>, external_type_ref: Some(<kind, name from the program
ObjectNode>) }` — the same shape L3 already gives a known-external object. Do NOT give it a
`to` string: `CombinedGraph.nodes` are workspace routines only (`combined_graph.rs:351-352`)
and the cones/SCC/summaries assume edges point at nodes (`detector_context.rs:913-950,
1240-1250`). Run calls into dependencies: `Opaque` (as today). Implicit triggers into
dependency tables: no edge, no uncertainty (as today). Program `Unknown(ObjectNotInGraph)`
(`edge.rs:247-255`) means exactly L3's "object named but not in indexed source", so map it to
`ExternalTarget` too, not to `unresolved-call`.

**Bindings for dependency callees (spec §7 "argument bindings"):** the var-ness exists.
Source dependencies: `DeclSurface::get(id).params[i].by_ref` (frozen `dep_meta`,
`full.rs:1137-1140`). Symbol-only: `RoutineNode.abi_params` (`src/program/node_extract.rs:
197-222, 375`) — only `AbiParams::Complete` is trustworthy; `Missing`/`CollapsedUntrusted`
must leave the binding `"unresolved-callee"`. Upgrading these bindings is a real
behaviour change on its own (CFG walker opaque path, d37 by-value case), so stage it as a
separate switch value with its own diff (see the order below).

### A5. Events

`build_event_graph(&ws.routines, &symbols)` (`src/engine/l3/event_graph.rs:243`) does not
read `ResolvedCalls`. Event-dispatch combined edges come only from it
(`combined_graph.rs:321-348`), and the event-flow indexes / cross-extension subscribers
too (`detector_context.rs:1181-1186`). Program call-site edges never contain event links:
event links are separate `ObligationId::Publisher` edges (`full.rs:862-874`); filter to
`ObligationId::CallSite` (`full.rs:87-94`). So **Phase A can keep L3's event graph
untouched**; swapping events is independent work (it would also change `SymbolTable`-based
publisher synthesis, `event_graph.rs:290-330`).

### A6. Operation sites

Record ops / `Commit` / error calls go to `operation_sites` and `record_operations`
(`ir_walk.rs:800-906`); record ops and `Commit` are kept out of `call_sites`
(`ir_walk.rs:907`). Error calls are BOTH an operation site AND a call site. Nothing in L3
call resolution writes operation sites; they feed capability facts, d8/d34/d35 etc. directly
from `L3Routine`. **Phase A leaves them on L2 untouched.** The program's RecordOp/Commit
sites resolve to catalog routes or implicit triggers; in the adapter they either join to an
`L3RecordOperation` (implicit triggers only) or are skipped and counted as "operation site,
no L3 call analogue". Shape disagreements (L2 says record op, program says call, or the
reverse) show up as unmatched sites and must be counted by reason.

## B. The new side

### B7. What the program engine gives per workspace call site

`ClassifiedEdge { obligation_id, edge: Edge { from, site, kind: EdgeKind{Call, Run,
ImplicitTrigger, EventFlow}, shape: DispatchShape{Exact, Polymorphic, Multicast,
DynamicOpen, AmbiguousOverload}, completeness, routes: Vec<Route{ target: RouteTarget{
Routine(NodeId), Builtin, AbiSymbol, Unresolved}, evidence: Evidence{Source, Abi,
Catalog, Opaque, Unknown(reason)}, conditions, witness, receiver_tier }> } }`
(`full.rs:87-100`, `edge.rs:94-456`). Outcome classes: `classify_obligation`
(`edge.rs:560-635`).

Route → L3 `CallEdge` conversion (adapter rules; dispatch kind comes from the L2 `PCallee`,
never from the L3 resolver):

| Program edge | L3 shape to emit | Bindings |
|---|---|---|
| Call, Exact, Routine route in workspace | `to: Some(L3 id)`, `Direct` (L2 `Bare`) or `Method` (L2 `Member`), `Resolved` | upgrade with callee `L3Routine.parameters[i].is_var` |
| Run, Routine route in workspace | `to: Some`, `CodeunitRun`/`PageRun`/`ReportRun` from `PCallee::ObjectRun.object_kind` (`call_resolver.rs:351-357`), `Resolved` | upgrade |
| Polymorphic (interface) | one `Interface`+`Maybe` edge per WORKSPACE route, sorted by `to`, `dispatch_meta` on the first (`call_resolver.rs:441-458`); none → one to-less `Interface` edge, `Unknown(InterfaceNoImpl)`; dependency implementer routes dropped and counted | all `"ambiguous"` |
| AmbiguousOverload | to-less, `Ambiguous`, `candidates` = workspace ids | `"ambiguous"` |
| DynamicOpen | to-less, `Dynamic`, `Unknown(DynamicReceiver)` | unchanged |
| Catalog route (builtin) | to-less, `Builtin` | unchanged |
| Routine route in a dependency / `ObjectNotInGraph` | to-less, `ExternalTarget` (Run: `Opaque`) | unchanged (stage 1) / upgraded from dependency var-ness (stage 2) |
| any other Unknown | to-less, `Unknown(<mapped reason>)` (e.g. `CatalogMiss`→`FrameworkMethodNotInCatalog`) | unchanged |
| ImplicitTrigger, workspace trigger route | `to: Some`, `ImplicitTrigger`, `Validate`→`Resolved`, others→`Maybe` (`implicit_edges.rs:45-54`), `callsite_id = operation_id = op.id` | none |
| ImplicitTrigger to dependency | no edge | — |

Interface name for `dispatch_meta`: the program `Edge` does not carry it. Take it from the
receiver variable's declared type in `L3Routine.variables` (pure L2 data). Low stakes:
`uncertainty_key` ignores it.

**One context for preflight and swap.** `ProgramContext` (`full.rs:1059-1075`) +
`resolve_full_program_with` (`full.rs:950-1018`) produce everything: `FreshCoverage` is a
pure reduction of the `ProgramReport` (`full.rs:1467-1472`), and the adapter needs the same
report plus `ctx.decl_surface()` and `ctx.graph()`. So yes: split `fresh_coverage` into
"build ctx + report" and "reduce report", call it once. Two costs to state in the plan:
- With the switch on, a preflight-cache hit can no longer skip the build
  (`full.rs:1446-1451` — on DO this skip was 2.6 s of a 3.2 s run, `full.rs:1440-1442`).
  The verdict can still be stored.
- Memory sequencing (spec §3; `full.rs:1430-1435`): the program model and L3 must not be
  resident together. Convert the report into a compact site table (key = exact span;
  value = kind, shape, and per route: workspace callee `(virtual_path, decl origin)` /
  dependency `(kind, name, Option<Vec<is_var>>)` / builtin / unknown reason), then drop the
  context BEFORE `assemble_and_resolve_workspace`. `Summary` dependency bodies are enough:
  the resolver resolves workspace files only (`full.rs:826-843`).

### B8. One parse

L3 re-parses at `l3_workspace.rs:673` (`al_syntax::parse(source)`); everything after it in
`project_file` uses only `ir_file` + `source`. A one-parse variant is a small split:
`project_file_ir(ir_file: &AlFile, source, ...)` fed from `ctx.parsed()` →
`ParsedFile { virtual_path, text, file }`, with `source_unit_id = "ws:" + virtual_path`.
What blocks it from being a pure refactor is headline finding 4: the file set and text
differ (nested apps, `.snapshots`, BOM, non-UTF-8). It also forces the workspace IR to
outlive the program context drop. **Not needed for Phase A.** Do it as a separate step
(A2) with its own difference run, after the file-set rules are made identical (or the
differences are proven harmless), so that a parse change is never confused with a
resolution change.

### C10. Minimal harness design

In-process, no CLI parsing, same `L3Resolved` for both runs so routine ids,
`rootCauseKey`s and fingerprints are directly comparable:

1. `old = assemble_and_resolve_workspace(ws, id, false)`; `run_detectors(&old,
   &registered_detectors())`.
2. Build `ProgramContext` + report; run the adapter against `old.workspace`; attach the
   result as the override on a second `L3Resolved` (or the same one, run twice);
   `run_detectors` again.
3. Diff findings keyed by `(detector, primary_location (unit, line, col), root_cause_key)`:
   `removed` / `added` / `changed` (same key; severity, confidence level/cappedBy, evidence
   path, message differ).
4. Attribution columns per difference: the L3 call sites inside the finding's routines
   (primary + evidence-path routines) whose old and new `CallEdge`s differ, with old
   resolution, new program evidence/`UnknownReason`. Plus a global per-site edge diff table
   and the adapter census (matched / unmatched by reason: no program site, program-only
   site, callee_fp mismatch, caller mismatch, callee outside L3 population, operation
   site, dependency route dropped).
5. Output a markdown/TSV triage table with an empty "verdict" column (fixed / regression /
   unexplained) for the `triage-findings` practice.

Where: an `aldump` mode (e.g. `--b3-detector-diff <ws>`) for CDO, DO, 8020 with
`--profile release-fast`; and a test that runs it over every `tests/r0-corpus/*` with an
`app.json` (215 dirs; several have no `app.json` and fail closed on both sides) and, once
triaged, asserts the result equals a committed triage ledger (zero `unexplained`, zero
`regression`).

## Riskiest point

The meaning shift at the edge of the workspace, not the site join. Every call that L3 left
`unresolved-call` (record-table procedures, bare calls into base objects) and the program
now resolves into a dependency changes its uncertainty kind; that moves finding
**confidence** (`confidence.rs:104-111`) and L4 side facts across many findings at once, and
the binding upgrade (step 5) flips CFG-walker and d37 branches. A second, quieter risk is
the forgotten second resolution site (headline 2): miss it and d47/d49/d51 diff as "no
change" while running on the old graph.

## Where the code contradicts spec §7 or is bigger than it assumes

- **UTF-16 vs byte columns**: false premise; both are byte columns (headline 3). No
  conversion is needed; keep the non-ASCII test as proof.
- **"L3's call resolution is replaced"**: there is no stored L3 resolution to replace;
  `resolve_calls` is re-run per consumer, and at least two consumers are on the analyze path
  (headline 2), plus four more off it that must stay on L3.
- **"L2 body facts built from the program engine's already-parsed trees"** is not a
  refactor: the two engines read different files and different text (headline 4). Split it
  out of Phase A.
- **Operation sites**: the only program obligations that map onto L3 data are implicit
  triggers, and they map to `L3RecordOperation`, not to `POperationSite`. Record-op catalog
  routes and `Commit` have no L3 analogue and are simply not used.
- **Events** need no translation in Phase A (A5); the spec lists them as an adapter duty.
- **Preflight cache**: one shared context means the cache can no longer skip the build when
  the switch is on (B7).
- **Spec line cites**: `detector_context.rs:1310-1320` for binding reads is off; the reads
  are at 1330-1337 (summaries) and 1477-1478 (detectors). `ir_walk.rs:279-294` is `lit_text`;
  the anchor builder is 262-276. `extract.rs:637-657` is right.
- **`--scope all`** has no effect on analyze today (`run.rs:327`); scope is a Phase C topic.
