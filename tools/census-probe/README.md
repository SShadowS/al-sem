# census-probe

Counting-allocator byte census of the LSP snapshots, one DepCache shared across roots; `--with-updaters` also starts each root's real updater and measures the idle heap. Accounting conventions (the local, untracked skill `.claude/skills/byte-census/SKILL.md` has the long form): a counting `#[global_allocator]` over `System` is the only size evidence; bytes are requested heap size, allocator overhead excluded; MiB = 1,048,576 B; "retained" = live heap once it stops moving for 0.9 s; "peak" = highest live heap during a build; OS RSS is context only, never a result. The probe is deliberately tracked under `tools/` (it is a measurement tool, not CI), and its own `[workspace]` table keeps it out of the repo workspace.

Build: `CARGO_TARGET_DIR=C:/lpt cargo build --release` here (own workspace; never build into the repo's `target/`). Run: `C:/lpt/release/census-probe.exe <embedded|symbols> <root>... [--with-updaters]`.

No gate compiles the probe, so it breaks silently when the crate's API moves. Before each step's re-run, check it first: `CARGO_TARGET_DIR=C:/lpt cargo check --manifest-path tools/census-probe/Cargo.toml` (from the repo root).

**Per-build output added for issue #84** (`embedded`/`symbols` modes, printed after each root's Q3 phase table):

- `build peak is in phase <mark>`: the census-hook phase (Q3 `on_mark`) whose in-phase peak equals the BUILD PEAK.
- `SymbolOnly units ingested by step 2b`: the snapshot's units with no source root, which `build_dep_nodes` step 2b passes to `ingest_abi` (and how many have an `app_path`), plus the dependency layer's `abi_ingest_errors` count. GUID grouping keeps one version per app, so this can be lower than the number of `.app` files.
- **Large-allocation log**: every `alloc`, `alloc_zeroed` and `realloc` whose NEW requested size is at least 8 MiB (8,388,608 B), one line each: the kind, the new size, the old size (realloc only), `live` (the net live heap right after the request, relative to before this root's build), `transient` (= live + old: during a realloc's copy the old and new blocks are both live, which the counting allocator's net accounting cannot see), and the phase (the census mark that ends the phase the request fell in). Under each line come the record's backtrace frames that name `al_sem`, resolved only when printed (file:line needs the probe's `debug = "line-tables-only"`). A record is flagged `[Vec<RoutineNode> cap N]` / `[Vec<ObjectNode> cap N]` when its size is a multiple of that `size_of` (printed on the first line) AND its backtrace passes through `build_dep_nodes` or `dedup_routines_preserving_genuine_overloads`. A size can be a multiple by chance (a sort's scratch buffer of `RoutineNode` also qualifies), so read the frames. `LARGEST Vec<RoutineNode>/Vec<ObjectNode> buffer in build_dep_nodes` names the largest flagged record. When a frame is inlined away, the phase still attributes the record.
- Mechanics: a `thread_local!` `const` `Cell<bool>` reentrancy guard; the backtrace (`backtrace::Backtrace::new_unresolved`) and the record push happen only while it is set, so their own allocations re-enter the allocator unlogged. They ARE counted in the live heap (a few KiB per record). Only roots that build the dependency tier cold (root 1, since all roots share one DepCache) show the `build_dep_nodes` records.
