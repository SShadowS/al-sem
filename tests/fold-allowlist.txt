# The one-fold guard (TLS-43, `src/fold_guard_tests.rs`).
#
# AL identifiers (object, routine, field, variable, parameter, method, receiver, table names)
# compare and key with ONE fold: `al_syntax::fold_identifier` / `eq_fold_identifier`. In
# src/engine and src/program, `.to_lowercase()`, `.to_ascii_lowercase()` and
# `eq_ignore_ascii_case(` are allowed only where the value is NOT an identifier:
#   - identity inputs that must not move (ids, fingerprints, root-cause and event-id keys);
#   - paths, file names, extensions, app/package names, GUIDs;
#   - fixed ASCII keywords, type text, char-level checks, display text;
#   - test code.
# Each line is `<count> <path>`: the exact number of those calls the file holds today. The
# guard fails when a count differs. A NEW call: use the identifier fold if it touches an
# identifier; otherwise raise the count here and say why in the commit. A REMOVED call:
# lower the count. Never fold an identity input without checking what reads the id.
#
# Limit: the guard counts per file, so swapping one call for another in the same file
# passes. Review such a swap like any fold change.
